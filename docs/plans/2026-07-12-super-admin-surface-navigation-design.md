# 超管三层入口导航修复设计

## 问题

超级管理员登录后持有平台范围画像，但登录页把会话直接落到 `/admin`。管理层侧边栏没有返回入口启动器的控件；从管理层切换工作区时，即使重定向目标是 `/launcher`，平台范围提交也会再次强制回到 `/admin`。

可观察结果是：超管权限画像包含应用层、执行层和管理层，但界面只展示管理层。

## 已批准方案

采用统一入口启动器：

1. 超管完成登录和首次改密后进入 `/launcher`。
2. 应用层、执行层、管理层的桌面侧边栏和移动菜单都提供“切换入口”，链接到 `/launcher`。
3. 平台范围的启动器展示三个入口。
4. 点击应用层时进入工作区选择，并要求选择机构；赛事可以不选。
5. 点击执行层时进入工作区选择，并预选首个可用赛事；没有赛事时不能伪造执行层上下文。
6. 点击管理层时保留平台范围并进入 `/admin`。
7. 工作区选择页收到 `/launcher` 重定向时，平台范围提交后回到启动器，不再强制回到管理层。

## 权限边界

| 上下文 | 应用层 | 执行层 | 管理层 |
| --- | --- | --- | --- |
| 平台 | 入口可见，进入前选择机构 | 入口可见，进入前选择赛事 | 直接进入 |
| 机构 | 可进入 | 不可进入 | 可进入 |
| 赛事 | 可进入 | 可进入 | 可进入 |

本次只修复导航可达性，不放宽后端权限画像，不用角色判断绕过工作区校验。

## 组件与数据流

```text
登录成功
  -> 写入 platform workspace session
  -> /launcher
  -> 管理层: /admin
  -> 应用层: /workspaces/select?redirect=/app -> 选择机构 -> /app
  -> 执行层: /workspaces/select?redirect=/ops -> 选择赛事 -> /ops
```

`SurfaceShell` 负责在桌面侧边栏和移动菜单注入统一的 `/launcher` 链接；三个业务层不各自复制入口切换逻辑。

## 验收标准

- 超管登录后的默认落点为 `/launcher`。
- 三个入口卡片可见。
- 每个业务层都能通过“切换入口”回到 `/launcher`。
- 平台范围不能绕过机构或赛事上下文直接打开应用层、执行层。
- 现有权限矩阵、工作区会话、路由和前端全量测试通过。
- 浏览器无控制台错误或未处理请求错误。
