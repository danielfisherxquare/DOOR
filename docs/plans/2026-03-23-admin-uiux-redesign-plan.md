# DOOR 管理后台 UI/UX 重构研究与实现方案

## 1. 研究结论

当前 DOOR 管理后台已经具备较完整的业务能力，但前端交互层存在三个结构性问题：

### 1.1 上下文隐藏，导致操作不直观

- 超管需要先选机构、再选赛事，但这两个动作都没有被提升为后台的“全局上下文”。
- 证件、号牌、授权、仓储等模块都依赖作用域，用户却要进入页面后才意识到自己是不是选错了对象。
- 结果就是用户经常处于“页面是对的，但对象是错的”的状态。

### 1.2 同一条业务链被拆散到多个页面

- 证件流程被拆成“选择赛事 / 通行区域 / 证件类别 / 样式 / 申请 / 审核 / 领取”多个平铺页面。
- 身份与权限被拆成“团队管理 / 用户管理 / 机构赛事授权 / 赛事授权”。
- 仓储作业被拆成“预入库 / 入库 / 扫码 / 打印 / 仓库 / 盘点 / 预警 / 报表”。

这种拆分方式适合后端接口划分，但不适合前端实际作业。

### 1.3 视觉风格偏“通用白卡片 SaaS”，不够工业化

- 目前的白底卡片、圆角按钮、轻阴影风格偏向普通工具站点。
- 对管理后台来说，缺少“控制台、调度台、作业中心”的稳定感与力度。
- 信息密度不够稳定，重要操作和普通内容视觉权重过近。

## 2. 当前可见的重复板块与建议重构方向

### 2.1 身份与权限中心

当前分散页面：

- `用户管理`
- `团队管理`
- `机构赛事授权`
- `赛事授权`

重复点：

- 都在处理“谁可以做什么”。
- 都在选择机构、用户、成员、赛事这些关联对象。
- 都有相似的列表、筛选、状态切换、授权动作。

建议：

- 重构为一个统一的 `身份与授权中心`。
- 按流程分成三个连续视图：
  - 成员档案
  - 账号开通与状态
  - 赛事授权
- 机构赛事授权作为上层范围控制，放在同一中心内的“机构范围”页签中。

### 2.2 证件流程中心

当前分散页面：

- `选择赛事`
- `通行区域`
- `证件类别`
- `证件样式`
- `申请与直建`
- `审核`
- `领取`

重复点：

- 所有页面都依赖同一个 `raceId`。
- 多个页面都在处理“证件规则 -> 申请 -> 审核 -> 发放”这一条链路。
- 页面之间跳转成本高，用户无法感知自己处在流程的哪一步。

建议：

- 重构为 `证件流程中心`。
- 顶部固定显示赛事上下文。
- 主体改为流程型二级导航：
  - 基础规则
  - 样式模板
  - 申请建单
  - 审核处理
  - 发放追踪
- 保留现有页面能力，但从“并列菜单”改成“连续流程”。

### 2.3 仓储作业中心

当前分散页面：

- `仓储概览`
- `入库前流程`
- `批量入库`
- `扫码领取`
- `二维码打印`
- `仓库管理`
- `3D 设计 / 查看 / 绑定`
- `盘点管理`
- `预警中心`
- `报表统计`

重复点：

- 都依赖相同的仓储对象、库位、批次、状态筛选。
- 用户在多个页面里重复切换“我在看哪个仓、哪个物料、哪个状态”。
- 工具型页面和操作型页面混排，认知层级不清晰。

建议：

- 以 `仓储作业中心` 为主入口。
- 结构改为：
  - 作业总览
  - 入库链路
  - 出库/领取
  - 空间与库位
  - 盘点与预警
  - 报表复盘
- `二维码打印` 作为支持工具并入相关作业分组，不再作为与主流程同级的独立模块。

### 2.4 系统运维区

当前分散页面：

- `数据库备份`
- `应用管理`

建议：

- 合并为 `系统运维区`。
- 与业务操作隔离，避免高风险动作与日常业务入口混排。

## 3. 交互改造原则

### 3.1 先锁定上下文，再执行操作

后台顶部必须常驻两个全局上下文：

- 目标机构
- 目标赛事

设计原则：

- 用户先看到“我现在在操作谁”。
- 再看到“我可以做什么”。
- 最后才进入具体列表和表单。

### 3.2 让流程比页面更重要

当前很多模块在信息架构上更像“功能目录”，而不是“作业流程”。

重构后应优先使用：

- 流程分段
- 连续步骤
- 待办优先级
- 上下文关联入口

而不是继续增加平铺菜单。

### 3.3 把高频近路从侧栏搬到工作区顶部

高频动作例如：

- 团队管理
- 赛事授权
- 证件建单
- 仓储概览

不应只藏在侧栏中。它们应该出现在顶部控制区，减少回退和寻找。

## 4. 视觉方向

### 4.1 风格关键词

- 工业风
- 现代运营控制台
- 数据密度高但秩序清晰
- 强调“控制”和“调度”感

### 4.2 建议设计语言

- 主色：工业灰
- 强调色：安全橙
- 辅助色：冷白、石墨黑
- 标题字体：更硬朗、紧凑
- 数字/编码：可使用等宽字体增强控制台感

### 4.3 应避免的视觉问题

- 继续沿用普通 SaaS 白卡片风格
- 圆润但没有层级的按钮系统
- 所有模块视觉权重过于平均
- 上下文状态不够突出

## 5. 本轮已落地实现

### 5.1 重构后台壳层 `AdminLayout`

已完成：

- 将导航按 `指挥总览 / 平台治理 / 组织与授权 / 证件流程 / 仓储作业` 重新分组。
- 将机构和赛事切换提升为顶部常驻上下文。
- 新增高频近路区，减少“回侧栏重新找页面”。
- 将视觉风格升级为工业灰 + 安全橙的控制台风格。
- 为依赖赛事的页面增加缺失上下文提示。

### 5.2 重构后台首页 `AdminDashboard`

已完成：

- 从“欢迎页 + 快捷按钮”升级为真正的作业指挥台。
- 将关键入口按 `平台治理 / 身份与授权 / 证件工作流 / 仓储作业` 组织。
- 首页直接说明交互改造重点、重复功能整合点和视觉方向。

## 6. 后续推荐实施阶段

### Phase 1：统一结构与上下文

- 完成后台壳层改造
- 统一顶部上下文
- 统一导航分组

### Phase 2：抽象后台通用工作区组件

- 页面头部
- 筛选栏
- 表格工作区
- 详情侧板/抽屉
- 状态提示条

目标：

- 解决当前各页面大量重复写 `标题 + 搜索 + 筛选 + 表格 + 操作按钮` 的问题。

### Phase 3：合并重复业务中心

- 身份与授权中心
- 证件流程中心
- 仓储作业中心
- 系统运维区

### Phase 4：细化页面级交互

- 批量操作
- 表格冻结列 / 汇总信息
- 详情抽屉替代部分弹窗
- 状态切换反馈
- 空状态与异常状态引导

## 7. 实现建议

从代码层看，下一步最值得做的不是继续单独美化某个页面，而是先抽通用后台框架：

- `adminConfig`：统一路由元信息、导航分组和上下文规则
- `AdminLayout`：统一壳层、上下文、近路和状态
- `AdminPageHeader / AdminFilterBar / AdminDataTable / AdminWorkbench`：统一页面结构组件

这样后续无论改证件还是仓储，都能在同一个设计系统下推进，而不是继续每个页面单独修补。
